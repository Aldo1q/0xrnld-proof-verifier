# ProofCheck — a public ZK proof verifier

**Agent:** 0xrnld (zkVerify Agent Games, Wildcard track)
**Live endpoint:** https://0xrnld-proof-verifier.vercel.app
**License:** MIT

## The problem

Zero-knowledge proofs are only useful if someone checks them. Today, checking
a Groth16 proof means installing tooling, finding the right verification key,
and running the verifier yourself — so in practice most proofs are never
checked by the people who rely on them. A claim backed by a proof is only as
strong as the number of independent parties willing to verify it.

## What this agent does

ProofCheck is a public agent that verifies **any Groth16 (BN128) proof**.
Send it a proof, a verification key, and the public signals; it answers
whether the proof is valid — in well under a second, with no sign-up, no
API key, and no trust required.

```
POST /verify
{
  "proof": { "pi_a": [...], "pi_b": [[...],[...]], "pi_c": [...] },
  "verificationKey": { "protocol": "groth16", "curve": "bn128", "nPublic": 13, "vk_alpha_1": [...], ... },
  "publicSignals": ["114215888...", "483614412...", ...]
}

-> { "valid": true, "protocol": "groth16", "curve": "bn128", "nPublic": 13, "ms": 12, "verifiedAt": "...", "reason": "proof verifies against the verification key and public signals" }
```

## Who it helps

- **Anyone handed a ZK proof** — an app, another agent, or a user who was told
  "this is proven" and wants to check it without setting up a toolchain.
- **Agent builders** who need a quick, independent second opinion on a proof
  before acting on it (e.g. before approving a payment or granting access).
- **Reviewers and auditors** who want a reproducible verdict: the same
  inputs verified locally with `snarkjs.groth16.verify` give the same answer.
  You never have to take this agent's word for it.

| Route | Method | Description |
|---|---|---|

| `/health` | GET | Liveness check |

## How it works

1. **Strict validation first.** The request is checked field by field: the
   proof must be `{ pi_a, pi_b, pi_c }` with correctly-shaped G1/G2 points,
   the verification key must be a well-formed snarkjs Groth16/BN128 key
   (`nPublic`, `vk_alpha_1`, `vk_beta_2`, `vk_gamma_2`, `vk_delta_2`,
   `vk_alphabeta_12`, `IC` with `nPublic + 1` entries), every value must be
   a valid BN128 field element (decimal or `0x`-hex strings accepted), and
   `publicSignals` must have exactly `nPublic` entries.
2. **Fail closed.** Malformed input returns HTTP 400 with a clear message —
   never a verdict. A malformed request is not a `valid: false` proof.
3. **Verify with snarkjs.** The normalised inputs are checked with
   `snarkjs.groth16.verify` (the reference Groth16 implementation). A
   well-formed proof that does not verify returns `{ valid: false }`.
   If verification itself throws (e.g. a point off-curve) that is also
   reported as invalid, never as an error that could be mistaken for a pass.
4. **Deterministic.** The same inputs always give the same verdict.

## Demo

`GET /demo` returns a real proof generated with the official zkVerify Agent
Games **Proof Gatekeeper** circuit (verification-key hash
`0x6b79c6012a6d8651f3e13bc4d2a20370280ab49700c90c5316d4168bfbad77b0`) — a
valid APPROVE decision — plus a tampered copy with one public signal changed
(`publicBalance` 1460 → 1461). Expected verdicts: valid → `true`,
tampered → `false`. The demo data lives in [`demo/example.json`](demo/example.json)
and is generated by `scripts/gen-demo.js` (never hand-written).

Reproduce it locally:

```bash
curl -s https://0xrnld-proof-verifier.vercel.app/demo > demo.json
# valid example -> expect { "valid": true }
curl -s -X POST https://0xrnld-proof-verifier.vercel.app/verify \
  -H 'Content-Type: application/json' \
  -d "$(node -e "console.log(JSON.stringify(require('./demo.json').valid))")"
# tampered example -> expect { "valid": false }
curl -s -X POST https://0xrnld-proof-verifier.vercel.app/verify \
  -H 'Content-Type: application/json' \
  -d "$(node -e "console.log(JSON.stringify(require('./demo.json').tampered))")"
```

Or verify the same proof entirely offline with snarkjs:

```js
const snarkjs = require("snarkjs");
const demo = require("./demo/example.json");
await snarkjs.groth16.verify(demo.valid.verificationKey, demo.valid.publicSignals, demo.valid.proof);
// -> true
```

## What it can and cannot do

- **Can:** verify any Groth16/BN128 proof (any circuit), fast, statelessly.
- **Cannot:** generate proofs (it only verifies); verify other proving
  systems (Plonk, STARKs, …); or judge what a proof *means*. Verification
  is necessary, not sufficient: a proof can verify perfectly and still
  authorise the wrong action if the circuit or the public inputs are wrong.
  This agent answers "does this proof check out?" — not "should you trust
  what it claims?"

## Run it locally

```bash
npm install
npm run gen-demo   # regenerates demo/example.json (needs the gatekeeper circuit; optional)
npm test           # 16 end-to-end checks (valid / tampered / malformed)
npm run build && npm start   # listens on :3000
```

## Stack

TypeScript + Node (no framework), `snarkjs@0.7.6` for verification,
deployed on Vercel as a serverless function (`api/verify.ts`) with a
long-lived server entry (`src/server.ts`) as the catch-all route.
Stateless — no database, no keys, no secrets.
